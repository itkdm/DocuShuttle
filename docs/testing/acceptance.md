# 第一阶段验收标准

## 核心用户流

- A：模板 + 示例 → 结构对齐 → 范围确认 → 生成 → 导出。
- B：只有模板 → 识别空白/说明 → 完成内容。
- C：只有示例 → 克隆原 OOXML → 识别个性内容 → 替换。
- D：选中区域自然语言修改 → 内联建议 → 接受/拒绝 → 新版本。
- E：图片候选 → 选择/重生成 → 应用 → 导出。

图片应用 API 的最小服务端闭环是：候选资产必须属于当前用户和 task；应用请求必须携带当前 revision 与稳定图片 `nodeId`；提交前必须重新 inspect/mutate/validate；数据库只接受 CAS 成功的新不可变版本。

每条流必须验证浏览器可见结果、API 结果、数据库状态、私有 Storage 对象以及导出 DOCX，不以 mock-only 成功代替。

## DOCX 回归矩阵

对空白表格模板、匹配示例、派生模板和多表格多图片真实报告执行 no-op、文本、表格单元格、图片、多轮修改、导出和重开。检查 OPC ZIP/XML/relationships、目标节点、媒体、样式、分节、页眉页脚和未修改部件指纹。

通过标准：导出可重开且无修复提示；目标节点精确变化；非目标变化为零或在有理由的白名单内；稳定 node ID 可从 UI/Agent 映射到新版本；不支持构造被明确报告。

## 一致性和恢复

- 旧 revision 写入返回 409，不覆盖新版本。
- HITL 暂停/恢复不重复已完成副作用。
- DeepSeek、APIMart、Storage 或文档写入失败时 current version 仍有效。
- 取消和重试产生明确终态与审计记录。
- 恢复历史版本创建新版本，不删除历史。

## 安全和部署

验证跨用户访问拒绝、RLS、签名过期、上传限制、恶意 ZIP/外链拒绝、速率限制、日志和 bundle 无密钥。生产 URL 必须 HTTPS 可访问，健康检查、迁移、回滚和关键链路日志可用。

## 最终浏览器门禁

产品完成前必须使用 DevTools MCP 直接操作已部署的纸上鸭网站，逐条跑通 A–E 核心流和刷新/恢复/失败重试。测试同时检查页面状态、无障碍焦点、控制台错误、网络请求、API 响应、数据库/Storage 持久化结果和下载 DOCX。外部平台控制台缺少登录态只能记录为平台配置限制，不能替代或跳过纸上鸭自身的真实浏览器验收。
